# 感知真值系统方案设计

> 本文描述设计动机与工程权衡，不重复 README 的目录说明。

## 1. 问题定义

机器人 / 无人机的深度估计与 3D 跟踪模型要迭代，需要大量带深度真值的训练与评测数据。真实 LiDAR 真值成本高、覆盖稀疏、难以规模化；因此工程上普遍用**多源伪真值（pseudo-GT）** + **质量校验** + **benchmark 闭环**来替代。

要解决的不是「把某个深度模型跑得多准」，而是三个系统问题：

1. **怎么生产**：多源伪标签如何互补，如何给出每个像素的可靠程度；
2. **怎么验**：伪标签自己也可错，如何量化它的质量、如何标定置信度；
3. **怎么用**：如何把评测结果变成可行动的迭代信号（哪些场景差、哪些样本该补采）。

## 3. 伪真值三路：为什么是这三种

| 源 | 覆盖 | 精度 | 失效模式 | 置信度依据 |
|---|---|---|---|---|
| 双目立体 | 稠密但剔遮挡后约 80% | 最高 | 弱纹理、遮挡、重复纹理、远距离小视差 | 代价曲线峰比 + 左右一致性余量 |
| SfM 三角化 | 稀疏，网格扩散后稠密但低分辨率 | 中 | 角点少、外参误差、扩散抹平边界 | 重投影误差 + 匹配峰比 + 对极残差 |
| 离线单目先验 | 全图 | 低（只有相对深度） | 尺度与场景结构强相关，物体级深度不可靠 | 固定低置信 + 边缘抑制 |

**设计取舍**：三者的误差模式尽量正交，融合才有信息增益；若三路都来自同一模型，融合只是自我强化。

## 4. 关键决策：为什么必须做源级可靠性校准

三个源的 `confidence` 不是同一把尺子：

- 双目的置信度来自代价体峰比，0.8 表示「匹配很确定」；
- SfM 的置信度来自 `exp(-重投影误差)`，0.8 表示「几何自洽」；
- 离线先验的置信度是人为设定的 0.3。

**几何自洽 ≠ 深度准**。若直接按 confidence 加权融合，低精度但覆盖全图的先验会持续把深度拉偏。本项目第一版等权融合的实测结果就是反例（见 `outputs/report.md` 第 2 节）：AbsRel 比单用双目差数倍。

解决方案是**用一小批带真值的留出标定数据估计源级可靠性**：

```
w_s = 1 / (ε + AbsRel_s)^2        # 逆误差平方
w_s ← w_s / max(w)                # 归一化，最优源为 1.0
最终权重 = 像素级 confidence × w_s
```

- 标定集用**独立 seed 生成**，评测帧完全不参与；
- 像素级 confidence 决定「这个像素这一帧信不信」，源级权重决定「这个源整体信不信」，两者相乘；
- 有效掩码仍由原始 confidence 决定，所以定权不会牺牲覆盖率；
- 融合后呈现**级联效果**：双目有效处双目主导，双目失效处由 SfM 补位，先验仅兜底。

这是本系统最有价值的一处工程结论：**真值系统先标定置信度，再谈融合。**

## 5. MAD 离群点门控

对每个像素，取三源深度的中位数，计算各源偏差与 MAD（中位绝对偏差）。偏差超过 `k × MAD` 的源把置信度乘 0.05，而不是直接丢弃：

- 直接丢弃会浪费「某源偶尔正确」的信息；
- 用中位数 + MAD 而不是均值 + 标准差，是因为三源时均值和方差都会被单个离群值污染。

## 6. Benchmark 设计

**场景切片**：normal / low_texture / dynamic / low_light / motion_blur / far，每一类针对一个已知失效机理，而不是随机划分。

**指标**：
- 深度：AbsRel、RMSE、SIlog、δ<1.25（含 1.25²/1.25³）、误差分位数、有效覆盖率；
- 3D 跟踪：MOTA、MOTP、IDF1、IDSW、DetA、AssA、单阈值 HOTA。

**回归闭环**：6 个方案自动消融（单源 / 两两 / 等权三源 / 校准三源）；按切片输出难度排序；按 16×16 图块挖掘 worst-case，给出坐标与误差，可直接转成补采清单；置信度分箱检查「高置信是否真的低误差」。

## 7. 已知限制与演进路径

| 现状 | 生产环境应做的事 |
|---|---|
| 合成渲染数据 | 接 `KITTIAdapter` 读 KITTI-360 / 自采双目 + LiDAR |
| 手写双目 SAD | 换 RAFT-Stereo / IGEV-Stereo，保留 LRC 与置信度框架 |
| 双目角点三角化 | 接 COLMAP 增量式 SfM、3DGS 渲染伪真值 |
| 手写离线先验 | 接 Depth Anything V2（相对深度）+ SAM（语义伪标签），接口已留 |
| 单阈值 HOTA | 按官方定义做多 IoU 阈值积分 |
| C++ 覆盖后处理与指标 | 把 SAD 代价体也下沉到 C++/CUDA，减少 Python↔C 边界穿越 |

以上是项目刻意保留的边界。本项目的定位是「完整跑通并验证了真值系统的数据流、误差来源与评测方法」，不是「复现了生产级 3D 感知系统」；上表同时给出了向生产环境演进的路径。
