# 复现指南

## 1. 环境

- Python 3.10+（开发验证环境：3.13.14 / Windows）
- 仅需 4 个包：`numpy`、`Pillow`、`matplotlib`、`pytest`
- **不需要** torch、CUDA、OpenCV、COLMAP、KITTI 账号或任何模型权重

```bash
git clone <repo-url> && cd perception-gt-bench
python -m venv .venv

# Windows
.venv\Scripts\python.exe -m pip install -r requirements.txt
# Linux / macOS
# python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

## 2. 三步跑通

```bash
python cpp/build_ctypes.py     # 可选：编译 C++17 内核
python scripts/run_all.py      # 全链路，约 30 秒
python -m pytest -q           # 19 个单元测试
```

`run_all.py` 会自动把 `src/` 加入 `sys.path`，无需 `pip install -e .`。

常用参数：

```bash
python scripts/run_all.py --seed 42 --out outputs_seed42
python scripts/run_all.py --no-viz
python scripts/run_all.py --config configs/my_config.json
python scripts/bench_native.py     # 单独看 C++ 加速比
```

## 3. 配置说明（`configs/default.json`）

| 段 | 关键字段 | 说明 |
|---|---|---|
| `camera` | `width/height/fx/fy/cx/cy/baseline` | 已极线校正的针孔双目；改分辨率需同步改 `cx/cy` |
| `dataset` | `slices`, `frames_per_slice`, `validation_frames` | 6 类切片各 4 帧 = 24 帧深度评测，8 帧连续序列做跟踪 |
| `stereo` | `max_disparity=64`, `window=5`, `lr_threshold=1.0` | 视差搜索范围、SAD 窗口、左右一致性容差 |
| `sfm` | `num_keypoints=350`, `reproj_threshold=1.5` | Harris 角点数、重投影误差置信度衰减尺度 |
| `fusion` | `mad_k=3.0`, `min_confidence=0.10` | MAD 离群门控倍数、有效像素最小置信度和 |
| `benchmark` | `topk_badcases`, `iou_threshold=0.25` | hard-case 数量、3D 跟踪关联阈值 |

`seed` 决定全部合成数据；同 seed 逐字节一致，有单元测试保证。

## 4. 编译 C++ 内核

`cpp/build_ctypes.py` 按以下顺序探测编译器：

1. 环境变量 `GTB_CXX`（可写完整命令，如 `GTB_CXX="clang++ -target x86_64-pc-linux-gnu"`）
2. `g++` → `clang++` → MSVC `cl`
3. `python -m ziglang c++`（`pip install ziglang`，自带 clang 工具链，**无系统编译器的 Windows 机器推荐**）

产物放在 `src/gtbench/_native.{dll,so,dylib}`，`native.py` 自动加载；加载失败时静默回退 NumPy，全链路依然可跑。

也可用标准 CMake 构建：

```bash
cmake -S cpp -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

## 5. 接入真实 KITTI / 自采双目数据

`src/gtbench/data/ingest.py::KITTIAdapter` 是唯一改动点。实现 `load_frame()` 返回 `data.synth.Frame`：

| Frame 字段 | KITTI 来源 |
|---|---|
| `rgb_left` / `rgb_right` | `image_2` / `image_3`（已 rectified） |
| `depth_gt` / `valid_gt` | `velodyne` 点云投影到左图；或 depth completion GT |
| `objects_gt` | `label_2` 的 3D box + track ID |
| `detections` | 你的检测器输出，或带噪的 GT 框 |
| Camera | `calib_cam_to_cam.txt` 的 `P2/P3`、`f`、`cx/cy`、`baseline = |tx| / f` |

下游 `pseudo_gt` / `gt_qc` / `benchmark` 全部只依赖 Frame 接口，**不需要改动**。

注意：真实数据未做极线校正时要先 rectify；LiDAR 真值稀疏，比较时务必统一有效像素口径（见 `指标定义与误差来源.md`）。

## 6. 接入真实基础模型

`pseudo_gt/foundation.py` 定义了 `FoundationBackend.predict(rgb) -> (relative_depth, confidence)`：

```python
from gtbench.pseudo_gt.foundation import DepthAnythingV2Backend

backend = DepthAnythingV2Backend(checkpoint="depth_anything_v2_vits.pth")
# 实现 predict(): 加载 torch 模型 -> 推理 -> 归一化到 [0,1] -> 返回置信度图
proposal = foundation_proposal(frame, cam, cfg.fusion, sfm_ref=sfm, backend=backend)
```

`SAMBackend` 同理，用语义掩码生成伪标签。默认跑的是 `GradientPriorBackend`（手写离线先验），**报告中任何数字都不包含真实大模型**。接入后请重新运行并更新报告，不要再引用旧数字。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| `no C++ compiler found` | `pip install ziglang`，或设置 `GTB_CXX`；不编译也能跑（NumPy 回退） |
| 图表中文乱码 | 图内标签已全部使用英文；报告 Markdown/HTML 为中文，不受字体影响 |
| 运行较慢 | 减小 `camera.width/height`、`stereo.max_disparity`、`dataset.frames_per_slice` |
| `new=0` | manifest 命中，说明断点续跑生效；换 `--seed` 或删除 `outputs/manifest.json` 可强制重算 |
| 数字和 README 不一致 | README 刻意不预置数字，一切以 `outputs/report.md` / `results.json` 为准 |

## 9. 引用指标时的口径

在文档或技术分享中引用本项目的实测数字时，请一律以本地运行生成的 `outputs/report.md` / `results.json` 为准，并同时带上口径：

- 说 AbsRel 必须说明**覆盖率 / 有效像素集**，不同覆盖率之间不可直接比较；
- 说「加速」必须区分**组合链路**与单算子，两者结论可能相反；
- 说「融合改善」必须说明是**相对未校准等权融合**，不是相对 stereo 单源；
- 不得表述为「在 KITTI 上验证」「使用 Depth Anything V2 / 3DGS / COLMAP」。
